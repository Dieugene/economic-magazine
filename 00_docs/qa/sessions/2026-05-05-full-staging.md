## Краткое резюме

Прогнан полный сценарий редакторского рабочего цикла на тестовом стенде: создание рубрик, создание трёх выпусков с разными статусами (Черновик, Готов, Опубликован), создание восьми статей разной полноты, правка полей, удаление, публикация и просмотр публичных страниц.

Базовая функциональность редакторской панели **работает**: формы заполняются и сохраняются, переключение статусов проходит, файлы загружаются, публичные страницы рендерятся.

Найдено **шесть дефектов**, перечислены ниже по убыванию серьёзности. Один из них — **критический и публично заметный**: на публичной странице опубликованного выпуска показываются статьи из черновиков другого выпуска. Этот дефект нужно закрывать в первую очередь.

## Найденные дефекты

### 1. (Критический) Статьи из неопубликованных выпусков утекают на публичные страницы

**Что происходит.** На публичной странице опубликованного выпуска показываются статьи, которые на самом деле принадлежат другому выпуску в статусе «Черновик» / «Готов». То есть посетитель сайта видит и может прочитать материалы, которые ещё не должны быть опубликованы.

**Как воспроизвести.**
1. Открыть `http://185.180.230.243/archive/2026/92/` — это опубликованный выпуск №92, в нём редакторами размещены три собственные статьи: «QA-A4 Два автора», «QA-A5 Длинные refs», «QA-A6 Без PDF».
2. Среди статей виден четвёртый материал — **«QA-A3 Cross»**.
3. Этот материал принадлежит выпуску №91, который в статусе «Готов» (не опубликован). Это можно убедиться, открыв `http://185.180.230.243/control/issues/10/` в админке: статья там, статус выпуска «Готов».

**Условие, которое порождает утечку.** Оба выпуска подписаны на одну общую рубрику «QA Пересечение 2026-05-05». Любая статья, лежащая в этой рубрике в *любом* выпуске, попадает на публичную страницу всех опубликованных выпусков, подписанных на эту рубрику.

В реальной жизни рубрики журнала (Экономическая теория, Методология и т. д.) — общие для большинства выпусков. То есть стоит хотя бы раз опубликовать выпуск с такой рубрикой, как все будущие *черновые* статьи в этой же рубрике начнут показываться на публичной странице этого выпуска.

**Техническая первопричина.** Эндпоинт `GET /api/issues/{id}/` возвращает поле `sections[*].articles`, в которое сериализуются все статьи рубрики глобально, без фильтра по `issue_id` сериализуемого выпуска. Публичный фронтенд рендерит этот массив напрямую.

**Что нужно сделать.**
- На бэкенде: в сериализаторе `IssueSection.articles` фильтровать по `issue_id` текущего выпуска.
- На фронтенде в качестве страховки: в публичном представлении выпуска отфильтровывать `articles.filter(a => a.issue_id === issue.id)`.

### 2. (Серьёзный) Сообщения об ошибках не доходят до пользователя

**Что происходит.** Когда сохранение или публикация не проходит, в админке показывается строка «API error: 400 Bad Request». Реальная причина (что именно не так с введёнными данными) не отображается, хотя бэкенд её возвращает.

**Как воспроизвести.**
1. Открыть в админке выпуск №91 (`/control/issues/10/`) — статус «Готов», PDF выпуска загружен.
2. Нажать «Опубликовать».
3. Над формой появляется красная плашка «API error: 400 Bad Request».

**Что должно показываться.** Бэкенд в этом случае возвращает структурированный ответ:

```json
{
  "status_code": 400,
  "error_type": "bad_request",
  "message": "В статье с ID 15 не загружен PDF документ"
}
```

То есть на стороне бэкенда уже есть готовый человеко-понятный текст. Фронтенд его игнорирует.

**Что нужно сделать.** В обработчике ответов в админке доставать `message` из тела ошибки и показывать его пользователю.

---

### 3. (Серьёзный) Бэкенд принимает любой файл с расширением .pdf

**Что происходит.** При загрузке PDF выпуска или PDF статьи бэкенд не проверяет, что внутри действительно лежит PDF. Можно загрузить, например, `.txt` файл, переименованный в `.pdf` — он будет принят и сохранён в файлохранилище как «PDF выпуска».

**Как воспроизвести.** Через инструменты разработчика отправить на эндпоинт `POST /api/issues/{id}/upload_pdf/` файл с произвольным содержимым (например, текстовый), но с расширением `.pdf`. Запрос завершится успехом (200), файл окажется доступен по ссылке `/media/issues/pdfs/{id}/...pdf`. На тестовом стенде такой файл сейчас лежит как PDF выпуска №93 (`http://185.180.230.243/media/issues/pdfs/9/not_a_pdf.pdf`).

**Что нужно сделать.** В upload-эндпоинтах выпусков и статей проверять «магические байты» / MIME-тип содержимого, отвергать файлы, которые не являются настоящим PDF.

### 4. Публикация выпуска без статей разрешена

**Что происходит.** Бэкенд позволяет перевести выпуск в статус «Опубликован», даже если в нём нет ни одной статьи. На публичной странице такого выпуска показывается «0 статей» и пустой блок рубрик.

**Как воспроизвести.**
1. Создать пустой выпуск, загрузить PDF выпуска и обложку.
2. Подписать выпуск на любую рубрику.
3. Нажать «Опубликовать» — статус меняется на «Опубликован» без ошибки.

На тестовом стенде такое состояние сейчас зафиксировано в выпуске №92 (`/archive/2026/92/` — на момент публикации в нём не было статей; статьи появились позже).

**Что нужно сделать.** На бэкенде при переводе выпуска в «Опубликован» дополнительно проверять, что в выпуске есть хотя бы одна статья. По смыслу — то же самое требование, что для PDF выпуска и PDF статей.

---

### 5. Создание статьи в уже опубликованном выпуске разрешено

**Что происходит.** Бэкенд позволяет добавлять и редактировать статьи в выпуск, который находится в статусе «Опубликован». То есть после публикации содержимое выпуска можно молча менять.

**Как воспроизвести.** В админке открыть страницу создания статьи с указанием опубликованного выпуска (`/control/articles/new/?issue_id=11`), заполнить форму, нажать «Создать». Статья создаётся.

**Что нужно сделать.** Решить с редакцией, можно ли менять опубликованный выпуск. Если нет — на бэкенде запретить создание/удаление/правку статей в опубликованных выпусках, а в админке прятать кнопки «Добавить статью», «Удалить» и блокировать редактирование полей.

---

### 6. Поле «Литература (русский)» не помечено обязательным, но обязательно

**Что происходит.** В форме статьи поле «Литература (английский)» помечено звёздочкой как обязательное, а поле «Литература (русский)» — нет. Однако если оставить русское поле пустым, бэкенд отвергает сохранение с ошибкой 400 (текст ошибки при этом ещё и не показывается — см. дефект №2).

**Как воспроизвести.** В форме новой статьи заполнить все поля кроме «Литература (русский)», нажать «Создать статью». Появится «API error: 400 Bad Request», статья не сохранится.

**Что нужно сделать.** Согласовать ожидаемое поведение и привести его в порядок:
- Если RU-литература действительно обязательна — поставить звёздочку и валидацию на фронтенде.
- Если она необязательна — на бэкенде разрешить пустую RU-строку.

## Что работает корректно

Перечислено для понимания границ выявленных проблем.

- Авторизация в админке, обновление просроченного токена в фоне.
- Создание, редактирование, переименование, поиск рубрик.
- Создание выпуска через форму.
- Подписка/отписка рубрик к выпуску через чек-боксы с сохранением.
- Загрузка обложки выпуска и PDF выпуска (с оговоркой по дефекту №3).
- Создание статьи через форму со всем набором полей: заголовок, авторы с аффилиациями, аннотация, ключевые слова, идентификаторы (DOI/УДК/JEL), даты, финансирование, литература.
- Загрузка PDF статьи.
- Редактирование любого поля статьи и сохранение изменений с сохранением после перезагрузки страницы.
- Удаление статьи.
- Поведение при выборе рубрики, не привязанной к текущему выпуску: рубрика автоматически добавляется к выпуску.
- Переход «Черновик» → «Готов» → «Опубликован» (с оговорками по дефектам №4 и №5).
- Корректное отклонение публикации выпуска без PDF выпуска и публикации выпуска со статьями без PDF (текст ошибки нечитаем — см. дефект №2).
- Публичная страница опубликованного выпуска `/archive/{год}/{номер}/` (с оговоркой по дефекту №1).
- Публичная страница статьи `/article/{id}/` с переключением языка RU/EN, корректные авторские плашки, лицензия Creative Commons 4.0.
- Сохранение спецсимволов (`«»`, `—`, `&`, `<тег>`, `O'Hara`) и длинных текстов в полях статьи.
