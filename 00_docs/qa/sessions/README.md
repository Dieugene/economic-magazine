# Test Sessions

Журнал прогонов тестового плана `../test_plan_issues_sections_articles.md`. Каждая сессия — отдельный markdown-файл; шаблон в `_TEMPLATE.md`.

## Соглашение об именовании

```
YYYY-MM-DD-<тег>.md
```

`<тег>` — короткая суть сессии в kebab-case:

- `smoke-pre-release` — короткий smoke перед релизом
- `regression-v0.1.11` — после конкретного билда
- `bug70-repro` — фокусное воспроизведение бага
- `exploratory-publish-flow` — exploratory по флоу публикации

Если в один день несколько сессий — добавить суффикс `-1`, `-2`: `2026-05-05-smoke-pre-release-2.md`.

## Жизненный цикл сессии

1. Скопировать `_TEMPLATE.md` → `YYYY-MM-DD-<тег>.md`.
2. Заполнить **метаданные** и **charter** ДО старта.
3. Тестировать, отмечая кейсы в **Coverage / Test log** в реальном времени.
4. Каждый FAIL → пункт в **Найденные баги**, дублировать в `00_docs/specs/backlog.txt` или `TaskCreate`.
5. По окончании — **Verdict** и рекомендация на следующую сессию.
6. Закоммитить (без сырых JWT и пароля в логах).

## Что не нужно

- Не редактировать чужие сессии задним числом — они снимок состояния. Поправки → новая сессия.
- Не дублировать в сессии содержимое тест-плана. Только результаты прогона + ссылки на номера кейсов плана (`S1`, `F3`, `E2.title`, `7.1`…).
- Не складывать сюда найденные баги «постоянного хранения» — для них `00_docs/specs/` или backlog.
