# Тест-план: Выпуски, Рубрики, Статьи

> **Назначение.** Сквозной ручной тест-план фронтенда ВТЭ по связке Выпуски ↔ Рубрики ↔ Статьи. Покрывает: отображение, редактирование, статусы выпуска, двуязычность, регрессии. Используется как чек-лист перед релизом и при отладке тёмных мест бэк-контракта (`Issue.sections`/`sections_slugs`).
>
> **Уровень тестирования.** Manual UI / E2E через браузер. Часть «насыщения базы» можно делать через UI или через curl (см. Приложение A).
>
> **Поддержка.** Документ обновляется при изменении контракта бэка либо при появлении нового регрессионного кейса (см. раздел [Регрессии](#7-регрессии)).
>
> **Журнал прогонов.** Каждый сеанс тестирования документируется отдельным файлом в `sessions/` по шаблону `sessions/_TEMPLATE.md` (SBTM-style: charter → coverage log → bugs → verdict). См. `sessions/README.md`. Тест-план — что проверяем; сессия — что фактически проверили, когда и чем закончилось.

## 1. Окружение и предусловия

| Параметр | Значение |
|---|---|
| Web | http://185.180.230.243/ (prod) |
| Admin | http://185.180.230.243/control/ |
| API | http://185.180.230.243/api/ (через прокси `/backend/...`) |
| Логин | см. `CLAUDE_CONTEXT.md` (раздел «Доступы») |
| Браузер | Chrome 137+, devtools открыты, вкладка Network |

**Предусловия:**

1. Сессия в админке активна (свежий JWT, нет 401 в network).
2. Тестовые данные, которые **не удалять** между прогонами: `issue 7` (как «маркерный» Draft), `issue 8` (`article 12` — живой кейс с PDF). Они нужны для воспроизведения регрессии бэка `IssueSection.articles` (см. §7.1).
3. Перед каждым большим прогоном — снять снимок текущего состояния списка `/control/issues/` и `/control/sections/` (скриншот или JSON `GET /api/issues/` + `GET /api/sections/`), чтобы можно было сверить «было/стало».
4. Бинарные фикстуры (PDF, обложки, fake-PDF) лежат в `fixtures/` рядом с этим планом. Манифест и инструкция восстановления — `fixtures/README.md`. Папка целиком в `.gitignore`, при свежем clone — восстановить по README.

**Важные допущения по контракту:**

- `Issue.sections_slugs: string[]` — write-only на POST/PATCH `/issues/`.
- `Issue.sections: IssueSection[]` — read-only на GET, **может содержать чужие статьи** (см. регрессия §7.1).
- Бэк отвергает POST/PATCH статьи, если `section.slug` не в `sections_slugs` целевого выпуска.
- Публикация `PUT /issues/{id}/update_status/` со `status: 'Published'` требует PDF выпуска **и** PDF каждой статьи.

## 2. Сценарий насыщения тестовой базы (seed)

**Цель.** Получить состояние, в котором есть достаточная вариативность для всех тестовых кейсов: разные статусы выпусков, разные рубрики (включая «свежесозданную, ещё пустую»), статьи с разной полнотой полей.

### Целевая форма базы (после seed)

**Рубрики (`/sections/`):**
| slug (примерно) | Название RU | Название EN | Назначение |
|---|---|---|---|
| ekonomicheskaja-teorija | Экономическая теория | Economic theory | существующая, наполненная |
| metodologija-… | Методология экономической науки | Methodology of economics | существующая, наполненная |
| qa-empty-section-* | QA пустая рубрика | QA empty section | **новая**, не должна получать чужие статьи |
| qa-cross-section-* | QA пересечение | QA cross | используется в двух выпусках одновременно |

> «*» — суффикс прогона (например, дата `2026-05-05`), чтобы не конфликтовать с предыдущими seed-ами.

**Выпуски (`/issues/`):**
| Маркер | Год / № / сквозной № | Статус | PDF выпуска | Подписанные рубрики |
|---|---|---|---|---|
| QA-DRAFT | 2026 / 90 / 90 | Draft | нет | `qa-empty-section-*` |
| QA-READY | 2026 / 91 / 91 | Ready | да | `ekonomicheskaja-teorija`, `qa-cross-section-*` |
| QA-PUBLISHED | 2026 / 92 / 92 | Published | да | `metodologija-…`, `qa-cross-section-*` |

**Статьи (минимум 7, оптимум 10), распределение:**
| ID-маркер | Выпуск | Рубрика | PDF | Особенность |
|---|---|---|---|---|
| QA-A1 | QA-READY | Экон. теория | да | полный набор полей (RU+EN, JEL, ORCID, refs) |
| QA-A2 | QA-READY | Экон. теория | да | без EN-аннотации (fallback) |
| QA-A3 | QA-READY | qa-cross-* | да | минимум полей |
| QA-A4 | QA-PUBLISHED | Методология | да | 2 автора, 2 affiliation |
| QA-A5 | QA-PUBLISHED | qa-cross-* | да | длинный список references (≥10) |
| QA-A6 | QA-PUBLISHED | Методология | **нет** | для проверки блокировки публикации (если статус будет переводиться) |
| QA-A7 | QA-DRAFT | qa-empty-section-* | нет | проверяет «свежесоздан­ная рубрика» |
| QA-A8 *(опц.)* | QA-DRAFT | Экон. теория | нет | **отрицательный** кейс: рубрика не подписана к выпуску → ожидаем 400 |
| QA-A9 *(опц.)* | QA-READY | qa-cross-* | да | спецсимволы в title (`«»`, `—`, `&`) |
| QA-A10 *(опц.)* | QA-PUBLISHED | qa-cross-* | да | очень длинный title (≥250 символов) для проверки truncate |

> QA-A8 — это специально провоцируемая ошибка контракта (см. §8.3). При корректной реализации фронт перед POST статьи делает PATCH `sections_slugs`, и она сохраняется. Тогда кейс превращается в позитивный.

### Порядок наполнения (через UI)

- [ ] **Шаг 1.** `/control/sections/` → создать `qa-empty-section-*` и `qa-cross-section-*`.
- [ ] **Шаг 2.** `/control/issues/` → «Создать номер»: QA-DRAFT, QA-READY, QA-PUBLISHED (год/номер из таблицы).
- [ ] **Шаг 3.** В каждом выпуске «Сохранить данные» с галками рубрик из таблицы.
- [ ] **Шаг 4.** Загрузить PDF выпусков для QA-READY и QA-PUBLISHED.
- [ ] **Шаг 5.** Создать статьи QA-A1…QA-A7 (минимум) через `/control/articles/new?issue_id=…`. Для каждой выбрать рубрику из подписанных к выпуску.
- [ ] **Шаг 6.** Загрузить PDF для всех статей, кроме QA-A6, QA-A7.
- [ ] **Шаг 7.** Перевести QA-READY → Ready, QA-PUBLISHED → Published. Если бэк ругается — зафиксировать, проверить, что причина известна (нет PDF у статьи) и описана в [тасках](#9-очистка-после-прохождения).

> Альтернатива через curl — см. Приложение A.

## 4. Smoke-сценарии

### S1. Список выпусков отображается корректно

**Шаги:** открыть `/control/issues/`.
**Ожидание:**
- Все три QA-выпуска присутствуют.
- Колонка «Статей» показывает фактическое число статей **именно этого выпуска** (см. §7.1).
- Колонка «Рубрик» = `issue.sections.length`.
- Бэйджи статусов: серый (Draft), медный (Ready), зелёный (Published).

### S2. Форма выпуска: статьи и рубрики

**Шаги:** открыть `/control/issues/{QA-READY.id}/`.
**Ожидание:**
- Чек-боксы рубрик отмечены ровно по `sections_slugs`.
- Список «Статьи номера» содержит только статьи этого выпуска.
- В каждой строке — title.ru, страницы, бейдж рубрики, иконки PDF/edit/delete.

### S3. Публичная страница выпуска

**Шаги:** `/archive/{year}/{number}/` (только Published доступны публично; ID не используется в публичном URL).
**Ожидание:** статьи сгруппированы по рубрикам, нигде не торчит чужая статья из другого выпуска.

### S4. Языковой переключатель

**Шаги:** на любой публичной странице переключить RU/EN.
**Ожидание:** title/abstract/keywords обновляются на язык UI; при отсутствии перевода — fallback с пометкой `(in Russian)` / `(на английском)`.

### S5. Сайдбар админа

**Шаги:** в админке.
**Ожидание:** видны пункты «Номера» и «Рубрикатор», оба переходят на свои страницы без ошибок.

## 5. Функциональные сценарии

### F1. Создание новой рубрики и её «пустота»

**Цель.** Убедиться, что свежесозданная рубрика не «всасывает» чужие статьи.

- [ ] **Шаг 1.** `/control/sections/` → «Добавить рубрику» → имя `QA Brand New {timestamp}`, en `QA Brand New`.
- [ ] **Шаг 2.** Дождаться ответа, увидеть рубрику в списке.
- [ ] **Шаг 3.** Перейти на публичную `/section/{slug}/` (если такой роут открыт публично) или открыть форму нового номера и убедиться, что рубрика появилась в чек-листе.
- [ ] **Шаг 4.** Проверить, что в карточке рубрики на публичном фронте список статей пуст.

**Ожидание:** статьи из старых рубрик в новой не появляются. При следующем шаге (создание статьи в этой рубрике в каком-то выпуске) — статья появится.

### F2. Привязка и отвязка рубрик к выпуску

- [ ] **Шаг 1.** В QA-DRAFT снять галку с `qa-empty-section-*`. Сохранить.
- [ ] **Шаг 2.** Перезагрузить страницу. Ожидание: галка не вернулась.
- [ ] **Шаг 3.** Поставить галку обратно. Сохранить. Ожидание: галка остаётся после reload.
- [ ] **Шаг 4.** Поставить галку на рубрику, которой в выпуске нет статей (например, новую из F1). Сохранить → reload. Ожидание: пусто, но галка стоит.
- [ ] **Шаг 5.** Поставить галку на рубрику, в которой есть статьи **в другом выпуске** (`qa-cross-*`). Сохранить → reload. **Ожидание контракта**: список статей формы остаётся пустым (т.к. бэк фильтрует `?issue_id=…`). Если в `IssueSection.articles` бэк отдаёт чужую — это **регрессия §7.1**, фиксируем.

### F3. Создание статьи: авто-привязка рубрики

**Цель.** Проверить, что фронт перед POST/PATCH статьи делает `ensureIssueHasSection`.

- [ ] **Шаг 1.** В QA-DRAFT снять все рубрики. Сохранить → reload.
- [ ] **Шаг 2.** Нажать «Добавить статью» из формы выпуска.
- [ ] **Шаг 3.** Заполнить поля, выбрать рубрику `qa-empty-section-*` (которой сейчас нет в `sections_slugs`).
- [ ] **Шаг 4.** Сохранить.
- [ ] **Шаг 5.** Вернуться на форму выпуска.

**Ожидание:** статья создана, рубрика автоматически добавилась в `sections_slugs` (галка стоит). В Network видно: PATCH `/issues/{id}/` с `sections_slugs` → 200, потом POST `/articles/` → 201.

### F4. Переходы статусов выпуска

- [ ] **Шаг 1.** QA-DRAFT → Ready: бэк должен принять (PDF выпуска не обязателен для Ready, но статус допустим). Если бэк отказывает — фиксируем как баг бэка.
- [ ] **Шаг 2.** QA-READY → Published: ожидание — успех, т.к. PDF и статьи на месте.
- [ ] **Шаг 3.** QA-PUBLISHED → Draft: бэк может либо разрешить (для отзыва публикации), либо запретить. Зафиксировать поведение.

### F5. Публикация без PDF — отрицательный

- [ ] **Шаг 1.** Создать временный выпуск QA-NOPDF (Draft, без PDF выпуска и без статей).
- [ ] **Шаг 2.** Попытаться «Опубликовать».

**Ожидание:** 400 с сообщением «В выпуске номера с ID … не загружен PDF документ». UI показывает сообщение в `saveError`.

### F6. Публикация с PDF выпуска, но без PDF статьи — отрицательный

- [ ] **Шаг 1.** В выпуске с PDF создать статью без PDF.
- [ ] **Шаг 2.** Попытаться «Опубликовать» выпуск.

**Ожидание:** 400 с сообщением «В статье с ID … не загружен PDF документ». См. таски `#91`/`#92` про UX-индикаторы и pre-publish guard.

## 6. Сценарии редактирования (CRUD)

> **Принцип**: для каждого редактируемого поля — Open form → Modify → Save → Reload page → Verify the value persisted. Без reload не считается.

### E1. Выпуск: редактирование данных

| Поле | Шаги | Ожидание |
|---|---|---|
| Год | 2026 → 2025 → save → reload | значение `2025` |
| Номер в году | смена → save → reload | новое значение |
| Сквозной номер | смена → save → reload | новое значение |
| Рубрики (мульти-чекбокс) | как F2 | как F2 |
| Обложка | upload jpg → save | ссылка обновлена, превью корректно |
| PDF выпуска | upload pdf → save | ссылка обновлена |

### E2. Статья: редактирование всех полей

Открыть QA-A1 в `/control/articles/{id}/`. Для каждого поля по очереди: изменить → сохранить → перезагрузить страницу → проверить, что значение сохранилось:

- [ ] `title.ru` / `title.en`
- [ ] `abstract.ru` / `abstract.en`
- [ ] `pages` (например `15-29`)
- [ ] `doi`
- [ ] `udk`
- [ ] `jel_codes` (через запятую/массив)
- [ ] `article_type` (Scientific/Review/…)
- [ ] `keywords.ru` / `keywords.en` (массив)
- [ ] `received_date`, `accepted_date`
- [ ] `funding.ru`, `funding.en` (en — условный, проверить, что пустая строка не падает с 400)
- [ ] `authors[]`: добавить, переименовать, удалить, поменять порядок (если есть кнопки), affiliations внутри автора, ORCID, email
- [ ] `references[]`: добавить, отредактировать ru/en, удалить, поменять порядок
- [ ] `section_slug`: сменить рубрику → проверить, что (а) `sections_slugs` выпуска расширился авто-PATCH-ем, (б) статья «уехала» в правильную секцию
- [ ] `issue_id`: перенести статью в другой выпуск (если UI это позволяет) — проверить, что в исходном её больше нет, в целевом появилась
- [ ] PDF статьи: загрузить / заменить
- [ ] XML/иные файлы: если поддерживаются

**Контроль:** после каждого save в Network должен быть PATCH `/articles/{id}/` со статусом 200, тело ответа должно соответствовать новому состоянию. Если 400 — фиксируем тело ошибки.

### E3. Удаление

- [ ] Удалить статью QA-A2 → подтверждение → исчезла из списка выпуска.
- [ ] Удалить выпуск (тестовый, не QA-PUBLISHED) → подтверждение → исчез из `/control/issues/`.
- [ ] Удалить рубрику — **в текущем UI запрещено** (только create/rename). Кнопки удаления не должно быть.

### E4. Редактируемость в зависимости от статуса выпуска

| Статус | Что должно быть редактируемым | Что НЕ должно |
|---|---|---|
| Draft | всё (данные, рубрики, статьи, обложка, PDF) | — |
| Ready | то же | — |
| Published | то же (UI пока не блокирует) | — |

> Если решено блокировать поля у Published — это будет отдельный таск; на текущем этапе фиксируем фактическое поведение и проверяем, что бэк не возвращает 4xx.

## 7. Регрессии

### 7.1. `IssueSection.articles` содержит статьи из других выпусков (баг бэка)

**Воспроизведение:**
1. `GET /api/issues/7/` через curl или вкладку Network.
2. В ответе `articles_count: 0`, но `sections[0].articles` содержит статью с `issue_id ≠ 7`.

**Симптомы во фронте:**
- В `/control/issues/` колонка «Статей» для issue 7 показывает `1` (фронт сейчас считает `sum(s.articles.length)`, см. `src/app/(control)/control/issues/page.tsx:163-167`).
- В `/issue/{published}/` (когда issue будет опубликован) — чужая статья отрисуется в карточке рубрики.

**Status:** ждём фикса бэка (фильтр `articles` по `issue_id` сериализуемого выпуска). На фронте — страховочный фикс: использовать `articles_count` всегда; в публичном `IssueView` — `s.articles.filter(a => a.issue_id === issue.id)`. См. `00_docs/specs/bug_70_issue_sections_empty.md` (родственный кейс).

### 7.2. `abstract: null` → 400 при создании статьи

**Воспроизведение:** POST `/articles/` с `abstract: null` → 400.
**Status:** исправлено в фронте (всегда `{ru:"", en:""}`). Регрессия — кейс E2/«создание статьи без аннотации».

### 7.3. POST статьи с `section_slug ∉ sections_slugs` → 400

**Воспроизведение:** убрать рубрику из выпуска, в форме статьи выбрать её, сохранить.
**Ожидание:** фронт делает PATCH `/issues/{id}/sections_slugs` ПЕРЕД POST/PATCH статьи. Без этого — 400. Кейс F3.

### 7.4. Двуязычное соседство на странице статьи (исторический)

**Контекст:** до 2026-05-03 на `/article/[id]/` показывались RU+EN параллельно (AbstractTabs, два блока References, дублирующий title).
**Ожидание:** теперь монолингвально по `lang`, с fallback-метками. Кейс S4.

## 8. Edge cases

### 8.1. Спецсимволы

В title статьи: `«Кавычки» — тире & «амперсанд»`, в keywords: `<тег>`, в author full_name: `O’Hara`.
**Ожидание:** сохраняются, корректно экранируются в JSX, не ломают вёрстку, не вызывают XSS.

### 8.2. Длинные строки

- title.ru ≥ 250 символов
- abstract.ru ≥ 5000 символов
- references — 30 элементов

**Ожидание:** UI не «лопается», работают `truncate`/scroll, бэк принимает или возвращает осмысленную ошибку.

### 8.3. Контрактный provoke: рубрика не подписана к выпуску

При выключенном `ensureIssueHasSection` (или принудительной правке Network), POST `/articles/` с `section_slug ∉ issue.sections_slugs` ⇒ 400.
**Ожидание:** в текущем UI авто-PATCH делается (см. F3). Если кейс ломается — это регрессия.

### 8.4. Свежесозданная рубрика в форме выпуска

- [ ] Создать рубрику.
- [ ] Сразу открыть форму существующего выпуска.

**Ожидание:** новая рубрика подгружается через `/sections/` без перезагрузки страницы (если используется `useEffect` без deps — могут понадобиться действия). Хотя бы после reload — должна быть видна.

### 8.5. Параллельная сессия

Открыть тот же выпуск в двух вкладках, в первой сменить год → сохранить. Во второй (без reload) сменить номер → сохранить.
**Ожидание:** последний save побеждает (last-write-wins). UI не должен крашиться.

### 8.6. Истёкший JWT во время заполнения формы

- [ ] Заполнить форму большой статьи.
- [ ] Подождать, пока `vte_admin_access` протухнет.
- [ ] Нажать «Сохранить».

**Ожидание:** клиент рефрешит токен через `/auth/refresh/` и завершает запрос; форма не теряет данные.

### 8.7. Загрузка не-PDF в поле PDF

- [ ] В поле PDF статьи выбрать `.docx`.

**Ожидание:** UI ограничивает `accept="application/pdf"` (диалог не покажет docx). Если файл всё-таки прокинули — бэк должен вернуть 400, UI — отрисовать ошибку.

## Приложение A. Скрипты seed через curl

> **Не пихать токен и пароли в коммиты.** Пользоваться переменными окружения. Пример для PowerShell:
>
> ```powershell
> $env:VTE_TOKEN = "Bearer eyJ..."
> $env:VTE_API = "http://185.180.230.243/api"
> ```

### A.1. Создать рубрику

```bash
curl -X POST "$VTE_API/sections/" \
  -H "Authorization: $VTE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":{"ru":"QA пустая","en":"QA empty"}}'
```

### A.2. Создать выпуск с подпиской на рубрики

```bash
curl -X POST "$VTE_API/issues/" \
  -H "Authorization: $VTE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "year": 2026,
    "number": 91,
    "sequential_number": 91,
    "sections_slugs": ["ekonomicheskaja-teorija","qa-cross-section-2026-05-05"]
  }'
```

### A.3. Загрузить PDF выпуска

```bash
curl -X PATCH "$VTE_API/issues/{id}/" \
  -H "Authorization: $VTE_TOKEN" \
  -F "pdf_file=@./VTE_qa.pdf"
```
